## 正式上线必须通过的发布门槛

缺少下列必需证据或学校正式验收时，不得创建 Release（正式版）；已发布源码候选不替代这些条件。

- [ ] 所有 P0 Issue 已关闭，或由学校责任人书面接受风险并设定到期日；
- [ ] `main` 只能通过 PR 合并，至少需要 1 名批准者和 `Backend tests` 必需检查；
- [ ] PostgreSQL 并发预约、数据库迁移、备份和恢复演练通过；
- [ ] 正式 AppID/AppSecret、HTTPS、合法域名和订阅模板已配置；
- [ ] 学生、辅导员、管理员完成注册/登录、预约、审批、签到、清扫和限制真机验收；
- [ ] 生产构建不包含 localhost、局域网 IP、HTTP 地址、空 AppID、默认密钥或关闭域名校验；
- [ ] Release notes 包含已知限制、数据迁移和回滚步骤；
- [ ] 验收数据不包含真实个人信息，截图和日志已脱敏。

## 版本规则

源码候选使用`v0.1.0-rc.N`，可在学校环境尚未齐备时按A节创建明确待部署验收的pre-release；rc.1已发布，后续文档补充不改变该标签或原包。完成全部上线门槛并获得书面验收后再创建稳定版本`v0.1.0`。候选执行release:check --candidate --tag；正式执行release:check --production --tag --evidence受控验收文件。原始CI、审批与签字须人工核对，脚本只检查材料与结构完整性。版本标签不可移动、复用或覆盖。

源码候选可以暂缺真实客户端截图。正式验收前须按 [截图说明](assets/screenshots/README.md) 补充真实脱敏证据；不得用设计稿或生成图替代。

逐项执行与签字模板见 [候选版发布清单](RELEASE_CHECKLIST.md)。
