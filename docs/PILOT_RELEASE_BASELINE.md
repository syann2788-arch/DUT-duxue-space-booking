# 校内试点发布基线

## 当前定位

项目当前定位为“校内试点候选”，不是正式生产版本。核心预约流程可在本地和真机调试中验证，但只有下列门槛全部完成后才能创建第一个 Release；任一必需项缺少证据时不得创建 Release。

## 试点里程碑建议

在 GitHub 新建里程碑 `v0.1.0 校内试点`，建议目标日期由学校在首次试点会议中确定。将下列 Issue 纳入并指定负责人角色和具体负责人：

- P0 安全与隐私：#1、#5、#6、#7、#9、#10；
- 确定性测试和质量门禁：#20、#22、#23；
- 生产配置与数据可靠性：#13、#14、#15、#16、#19；
- 真机关键链路：#17、#21。
- 发布与协作：#24、#25、#26。

| Issue 范围 | 默认负责人角色 | 状态要求 |
|---|---|---|
| #1、#6、#7、#9、#10 | 安全维护者 + 学校数据责任人 | 关闭或书面风险接受 |
| #5 | 学校身份平台负责人 + 后端维护者 | 外部方案确定并验收 |
| #13-#16、#19 | 学校运维 + 发布维护者 | 生产等价环境证据 |
| #17、#18、#21-#23 | 小程序/测试维护者 | CI 与真机证据 |
| #24-#26 | 仓库所有者 + 书院试点负责人 | 版本、模板、演示和指标可审计 |

## 必须通过的发布门槛

- [ ] 所有 P0 Issue 已关闭，或由学校责任人书面接受风险并设定到期日；
- [ ] `main` 只能通过 PR 合并，至少需要 1 名批准者和 `Backend tests` 必需检查；
- [ ] PostgreSQL 并发预约、数据库迁移、备份和恢复演练通过；
- [ ] 正式 AppID/AppSecret、HTTPS、合法域名和订阅模板已配置；
- [ ] 学生、辅导员、管理员完成注册/登录、预约、审批、签到、清扫和限制真机验收；
- [ ] 生产构建不包含 localhost、局域网 IP、HTTP 地址、空 AppID、默认密钥或关闭域名校验；
- [ ] Release notes 包含已知限制、数据迁移和回滚步骤；
- [ ] 验收数据不包含真实个人信息，截图和日志已脱敏。

## 版本规则

首次试点候选建议使用 `v0.1.0-rc.1`。完成全部门槛并获得书面验收后再创建 `v0.1.0`；版本一经发布不得移动标签，应通过后续版本修复问题。

逐项执行与签字模板见 [候选版发布清单](RELEASE_CHECKLIST.md)。
