# 老师需求对照与验收说明

依据《空间预约小程序开发需求说明书》和最新确认规则整理。老师文档中“固定5个选项”实际只列出4项，系统按自习、开会、大型活动、音乐练习四个场景实现。

## 已落实规则

| 需求 | 当前实现与验收点 |
|---|---|
| 半小时预约、单日最多4小时 | 后端按绝对分钟累计，超限返回400；后台可修改参数 |
| 23:00自动审批 | 后台分钟任务按配置时间自动通过未处理申请，保留自动审批标记 |
| 自习分房 | A102（6人）→ A101（10人）→ A105（10人），共享，一人一约 |
| 开会分房 | A105 → A101 → A102，独占，不设置固定参会人数上限 |
| 大型活动 | 仅A103，独占 |
| 音乐练习 | B102优先；B102占用时可分配A103钢琴；A103钢琴仅15:00–21:00 |
| A103互斥 | A103上的大型活动与音乐练习按同一物理房间锁定，重叠时段不能同时成立；B102保持独立 |
| 玉兰卡 | 提交预约前必须上传图片；预约记录和管理端审批页展示照片 |
| 清扫闭环 | 未上传照片时禁止下一笔预约；照片提交成功立即解锁；管理员异步通过或退回重传 |
| 违约处理 | 不设信用分；未签到、清扫不合格记为有效违约；每累计3次自动禁约30天 |
| 人工限制 | 管理员可设置1天、7天、30天、自定义天数或永久限制，并填写原因、随时解除 |
| 用户管理 | 支持按姓名、学号、手机号、班级搜索；可查看违约与限制记录 |
| Excel导出 | 支持日期范围、场景、状态筛选；包含用户、预约、审核、玉兰卡、清扫、违规字段及独立限制记录表 |
| 消息提醒 | 提交、审核结果、开始提醒、待清扫、清扫不合格、限制、解除和到期事件均写入可靠消息队列 |
| 系统参数 | 时长、开放时间、审批时间、提醒、违约阈值/天数、A103钢琴时段、分房优先级/容量均可后台修改 |

## 需求解释

1. 老师文档前文称B102是音乐专属房间，后文又说明A103钢琴可供音乐练习。系统采用“B102优先、A103钢琴作为第二候选”的一致解释。
2. 文档同时写“大型活动优先”和“已有音乐预约时大型活动不能抢占”。系统不撤销已经成立的音乐预约；大型活动先成立时会锁住A103，符合不可抢占原则。
3. 学生姓名、学号、联系方式来自已登录账号，预约时无需重复填写，管理员审批和导出仍可查看。

## 仍需校方/微信平台提供

1. 正式小程序AppID，并把开发者微信加入项目成员。
2. 四类订阅消息模板ID及对应字段。
3. 学校HTTPS API域名、服务器和数据库连接信息。
4. 正式环境中的玉兰卡/清扫照片持久化与访问策略，建议使用校内对象存储或受控文件服务。

未配置以上外部信息时，本地微信开发者工具仍可完成页面、预约、审批、冲突、清扫、违约和导出逻辑验收，但不能完成真实手机订阅消息发送。
