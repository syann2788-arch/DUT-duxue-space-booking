# 15 分钟匿名演示与验收流程

本流程只允许在本地开发环境、独立演示数据库和虚构账号上运行。不得使用真实学生姓名、学号、手机号、玉兰卡、清扫照片、OpenID 或学校生产凭据。

## 目标

用正式 `miniprogram/` 客户端演示“空间导览 → 学生预约状态 → 管理员审核 → 签到 → 清扫提交/复核”的产品闭环，并说明自动分房、冲突裁决和限制规则相对群聊/表格登记的价值。

## 0–3 分钟：准备

在仓库根目录创建本地环境并安装依赖。先启动独立演示数据库：

macOS/Linux：

```bash
cd backend
ALLOW_DEMO_SEED=1 ../.venv/bin/python demo_seed.py
../.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Windows PowerShell：

```powershell
Set-Location backend
$env:ALLOW_DEMO_SEED = "1"
..\.venv\Scripts\python.exe demo_seed.py
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

脚本会拒绝 production 或 PostgreSQL，只生成以下虚构账号：

| 角色 | 学号 | 密码 | 用途 |
|---|---|---|---|
| 学生 | `20269901` | `Demo1234` | 待审核、当前签到窗口、待清扫记录 |
| 辅导员 | `20269902` | `Demo1234` | A106 权限演示 |
| 管理员 | 本地 seed 演示账号 | 见本地开发说明 | 审核与复核 |

导入仓库根目录到微信开发者工具，确认加载的是 `miniprogram/`，编译后开始演示。

## 3–6 分钟：学生空间导览与预约

1. 登录虚构学生账号。
2. 在“空间导览”说明公开/可预约/不可互动空间的区别。
3. 进入“按场景发起预约”，切换自习、会议、活动和音乐，观察人数、候选空间和连续时段。
4. 说明系统按权限、容量、优先级和物理房间冲突统一裁决，不依赖管理员手工在群聊中比对。
5. 如实际提交预约，玉兰卡位置只能选择仓库 `miniprogram/static/logo.png` 或另行制作的纯色虚构图片，不得选择真实证件。

## 6–9 分钟：我的预约、分页和恢复

1. 在“我的”依次查看全部、待审核、待使用和待清扫。
2. 下拉或点击“加载更多”，确认分页总数和失败重试状态。
3. 对“当前签到窗口预约”执行签到；如果运行时段跨日导致窗口变化，重新执行 `demo_seed.py` 刷新时间。
4. 对“待上传清扫照片”上传同一张虚构图片，确认进入后台复核队列。

## 9–12 分钟：管理员闭环

1. 使用本地演示管理员登录，进入管理后台。
2. 在预约审核中找到 `[演示]` 记录，执行通过或驳回。
3. 在清扫复核中查看虚构图片，分别说明“通过”和“退回并限制”的业务结果。
4. 搜索 `20269901`，检查违约、限制和解除入口。
5. 展示分房规则、运行参数、Excel 导出和签到码内容。

## 12–15 分钟：辅导员权限与结果记录

1. 登录 `20269902`，确认 A106 辅导员预约记录与学生权限不同。
2. 回到 [需求追踪](REQUIREMENTS_TRACEABILITY.md) 逐项说明已实现、外部依赖和明确暂缓项。
3. 将本轮结果填入 [试点指标](PILOT_METRICS.md) 和 GitHub“试点验收记录”，只保存汇总数字和脱敏证据。
