# 学生、辅导员与管理员使用教程

适用于2026-10-02的`0.1.0-rc.1`候选源码。以当前原生小程序页面为准；尚未通过学校真机/真人验收。学校部署地址、联系人和隐私政策由学校另行填写。本教程不提供真实账号、密码或照片。

## 使用前准备

从学校提供的体验版/正式入口打开小程序。开发者本地调试见 [README](../README.md)，不能让普通用户使用开发电脑的127.0.0.1地址。先确认姓名、学号、联系方式及照片使用告知；有疑问联系书院业务管理员。

注册成功即创建启用的学生账号，不存在独立“激活”按钮，也不表示学号归属经过学校认证。当前需要学校另定可信注册与人工身份核验流程。辅导员、管理员角色不能靠自行注册或填名字取得。

## 学生申请与使用

1. 在登录页输入学号/密码；没有账号时进入“注册”，填写数字学号（4–20位）、姓名、11位有效手机号、4位班级和含字母/数字的密码（至少6位）。班级如2601，显示为“笃学2601”。只填本人信息。
2. 在“空间导览”查看房间、楼层与公开空间状态；点击房间看占用时间轴和介绍。时间轴不公开其他学生姓名和理由。能查看房间不代表能预约该房间。
3. 点场景入口或“＋ 发起预约”，选择自习、开会、大型活动、音乐练习之一，填写人数、日期与连续时段。默认开放08:00–22:00、每格30分钟、可提前7天、每天合计4小时；实际以管理员配置和页面提示为准。
4. 选择时段后进入申请表，填写用途并上传清晰玉兰卡照片。自习固定1人、用途默认“个人自习”；其余场景用途至少10字。选择连续区间需要有同一候选房间可覆盖整段。
5. 提交后服务器自动分配房间，记录订单号、房间和时间，到“我的”查看状态。选择场景不锁定房间；多人同时操作时可用性可能变化，以提交结果为准。上传成功但申请失败时按提示重新操作，不重复快速提交。
6. 在“我的”筛选预约，查看审核和清扫备注；“待审核”尚未获准使用。管理员可人工审核，独立worker按配置时间自动审批（默认23:00），服务器中断可能导致延迟。
7. 不需要使用时，在订单上的“取消预约”按钮操作；默认开始前至少30分钟可取消。超过截止时间按钮不显示或服务端拒绝，联系管理员处理业务例外，不能靠退出小程序取消。
8. 获批后在规定签到时窗内按“签到”，或“扫码签到”扫描对应房间的签到码。默认可从开始时刻至开始后15分钟签到；码只是房间标识，不会绕过当前预约和时间校验。
9. 使用结束后整理空间，在“我的”对相应订单点清扫上传按钮，提交实际清扫照片（最多6张）。未上传会阻断新预约；成功提交照片先解除该阻断，管理员再复核。被退回时读清扫备注、重新整理/上传。
10. “已完成”表示清扫复核通过。再次预约会重新进入场景选择，不保证分配原房间。已完成的使用仍计入当天额度；取消/驳回不计入。未签到、清扫不合格可形成违约，不因重新上传而删除历史记录。

| 场景 | 当前默认分配逻辑 | 用户应注意 |
|---|---|---|
| 自习 | A102→A101→A105，共享 | 一人一约，按实际人数累计容量 |
| 开会 | 学生A105→A101→A102，独占；辅导员优先A106 | 人数须满足当前容量规则 |
| 大型活动 | A103，独占 | 与同一物理房间的音乐预约冲突 |
| 音乐练习 | B102优先，A103钢琴备选 | A103默认15:00–21:00；不保证指定乐器/房间 |

会议容量解释、申请前指定房间预览、冰箱共享登记仍待学校决定；当前只有房间介绍中的冰箱属性，没有冰箱物品登记模块。

## 消息、限制与账号安全

“我的”→“通知设置”请求微信订阅授权；拒绝授权不会撤销预约。通过“消息记录与发送状态”查看业务消息和发送结果。记录存在、发送成功或看到“失败/未绑定”不能替代主动查看预约状态；微信绑定、模板和真实消息必须学校配置才能工作。

“我的”显示当前预约限制及原因。累计违约默认每3次禁约30天，参数可改；管理员也可设临时/限时/永久或未来起止区间。限制只在有效区间阻断，解除不删除审计历史；有异议提供订单号联系管理员。

“我的”→“修改密码”：填写当前密码、新密码与确认。新密码至少8位、含字母和数字，不超过72字节，不能与旧密码相同；成功后旧登录失效，需要重新登录。不要把密码放在备注、留言或截图。

### 忘记密码与人工恢复

1. 登录页“忘记密码”→“查看处理方式”，按学校指定渠道联系管理员。当前没有短信验证码服务。
2. 管理员通过学校流程核验本人后，给本人一条一次性重置凭证，30分钟内使用；该凭证等同短期恢复权限，不交给其他人。
3. “忘记密码”→“已取得重置凭证，设置新密码”，输入凭证、新密码和确认后提交。
4. 成功后以新密码重新登录。旧登录会话与旧微信绑定均撤销，之后按提示重新绑定微信/设置通知。
5. 凭证过期、已使用或被管理员重发后失效；重新联系管理员，不重复使用旧凭证。

## 辅导员首次登录

辅导员账号由授权CSV导入或后台受控创建。管理员通过受控渠道分别发放登录标识与随机初始密码；标识可能为手机号或`staff_姓名`，按实际发放值登录，不自行猜测学号。

首次登录自动进入改密页；未换密时业务接口受限，必须用初始密码完成修改，再以新密码登录。辅导员在开会场景可获得A106优先候选；角色权限由数据库确认，普通学生不可获得A106。其他预约、签到和清扫流程与学生一致。

## 管理员操作

正式管理员由学校运维在服务器运行`create_admin.py`交互创建；演示`admin001/admin123`不可用于学校生产。管理员自己的忘记密码恢复应由另一位授权管理员核验处理；脚本不覆盖已有账号，也不提升已有学生权限。

登录后“我的”→“管理后台”，可横向滚动标签。每次改规则/限制/密码前核对目标用户或订单；批量处理先复查已选择记录。

| 标签/入口 | 操作步骤与结果 |
|---|---|
| 概览 | 查看待审核、清扫、今日预约和用户数；按日期/场景/状态导出Excel；生成/预览房间签到码，张贴前再次核对房间 |
| 预约审核 | 查看日期、时间、人数、用途和玉兰卡；选择通过/驳回并填写备注，支持多选批量。驳回理由应可让申请人理解 |
| 全部订单 | 设开始/结束日期、场景、状态筛选；查看玉兰卡/清扫照片和备注。加载更多继续查历史，不能把当前加载数当总数 |
| 违规与清扫待办 | 切换“未上传清扫”“清扫不合格”“全部违约订单”“违规未完结”，查看联系方式并按学校流程提醒；待办查看本身不审批或改状态 |
| 清扫复核 | 查看实际照片，选择通过或退回并写备注；退回生成清扫不合格记录，可另选限制。通过使订单完成；退回后用户须重传 |
| 用户 | 按姓名/学号/手机号/班级搜索、点用户详情；查看违约/限制、添加或解除限制、签发恢复凭证 |
| 分房规则 | 改优先级（越小越优先）、容量、共享/独占、启用状态，再“保存此规则”；禁用用于暂停规则，重新初始化不会覆盖现有配置 |
| 系统配置 | 改开放时间、粒度、每日时长、提前天数、取消/签到、审批/提醒、违约阈值等；“保存全部配置”，服务器拒绝冲突组合 |
| 操作日志 | 查看操作时间、操作者ID、动作与目标；`系统/受控脚本`表示CLI记录。日志不提供明文密码/恢复凭证；照片访问另有媒体审计 |

### 禁约与解除

用户详情选择临时/限时/永久等级，填写原因。临时/限时可填天数，或明确开始日期时间、结束日期时间；天数与明确结束不能同时填，结束必须晚于开始。永久不填结束/天数。未来开始区间在开始前不生效；页面按北京时间显示。解除前核对用户和原因，解除只撤销该条限制，其他有效限制可能仍阻断预约。

### 管理员签发恢复凭证

先完成学校本人核验，不凭“知道学号”直接重置。在用户详情输入“核验原因”和**当前操作管理员自己的密码**，签发后复制一次性凭证，经受控渠道交给已核验本人；不要写入Excel、普通群聊或日志。重发使前一凭证失效。本人修改管理员自己的密码使用“我的→修改密码”，不能给自己签发恢复凭证。

### 导出与照片链接

概览选择日期范围（开始不能晚于结束）、场景与状态，点“导出Excel”。文件可能包含姓名、联系方式、用途、限制记录及私密媒体链接，按学校授权范围保存/分发。照片链接需要管理员登录鉴权，粘贴到公开浏览器不会直接获得图片；无权限、媒体过期/清理后会失败。链接不能视为照片永久存档，截图也须脱敏。

### 辅导员导入与初始密码发放

概览→“辅导员CSV导入”，从微信文件选择授权UTF-8 CSV。建议按仓库`Sheet_20250907.example.csv`字段准备“职务、姓名、负责班级、联系方式”；人员岗位和账号冲突需管理员人工核对。已有辅导员保留密码，已有学生/其他角色冲突时拒绝，不自动提升权限。

导入结果的新账号凭据只显示/复制给管理员，立即转存学校受控凭据库并逐人发放；不要把全表发给所有人，发放完成清理剪贴板与临时文件。CLI方式输出权限0600的文件，步骤见 [运行手册](OPERATIONS_RUNBOOK.md)。新辅导员首次登录强制换密。

## 遇到问题时

| 现象 | 处理 |
|---|---|
| 登录过期/改密后失效 | 重新登录；恢复后重新绑定微信 |
| 没有可用时段/申请失败 | 减少人数或改日期/场景，确认额度、连续区间、限制和清扫状态；不要反复点击 |
| 上传失败 | 核对图片格式/大小（默认每张上限8MB）、网络和实际HTTPS；原申请成功与否先在“我的”确认 |
| 通知失败 | 先查看订单；检查订阅授权，管理员联系运维检查模板/worker，不重复创建预约 |
| 列表加载失败 | 点“重新加载”或加载更多的重试提示；仍失败记录时间、页面、订单号和请求编号交管理员 |
| 清扫退回/禁约有异议 | 查看备注、提供订单号按学校流程处理，不绕过账号限制 |

不得在公开Issue/群聊放真实学号、手机号、玉兰卡、密码或凭证。

## 学校操作验收记录

由一位非开发人员按教程使用**虚构数据**，另一位管理员配合审核。记录设备/系统、候选提交、执行人和时间，完成注册→四场景各一申请→审核/取消→签到→清扫通过/退回重传→限制/解除→人工恢复→辅导员换密/A106→Excel/照片→消息成功与失败提示。另在iPhone和Android复核。

本地接口/纯逻辑验证已有证据，真人按教程和当前页面截图仍待学校安排；没有用设计稿或生成图代替实际截图。可将真实脱敏截图放入 [截图目录](assets/screenshots/README.md)，将签字记录按 [发布清单](RELEASE_CHECKLIST.md) 留存。
