# 源码候选交付与正式上线发布清单

当前准备版本：`v0.1.0-rc.1`。与 [发布基线](PILOT_RELEASE_BASELINE.md)、[交付指南](HANDOVER_GUIDE.md) 配套。根据本轮“先交源码、再由学校部署验收”的范围，区分两个阶段；以下规则变更须随PR交由维护者审核。本轮只制作本地候选材料，不自动创建标签、Release或上线。

## A. 候选源码交接（待部署验收）

学校服务器、AppSecret、真实HTTPS地址和正式签字可继续待办；接收源码不是确认学校系统已经可用。允许先准备本地包；创建候选GitHub Release前必须满足本节，未通过时不得创建 Release。

- [ ] 版本为`x.y.z-rc.N`，固定完整提交；已合入main，最新四项CI成功，评审/分支规则按真实记录核对。
- [ ] 维护者确认该次候选交付/预发布及公开范围，代码/标识/图片权利已核对；没有暴露密钥或真实人员数据等未处理风险。
- [ ] 包含源码ZIP、候选交付材料ZIP、使用/部署/微信/运维教程、配置模板、已知限制、逐文件清单及SHA256SUMS。
- [ ] 源码包来自目标Git提交，解压/重建验证通过；标签若存在必须对应同一提交，不打包整个开发目录。
- [ ] 可选微信构建包使用学校确认的AppID/HTTPS地址，版本与提交一致且独立校验通过；配置不齐时明确不附构建包。
- [ ] `npm run release:check -- --candidate --tag`在干净仓库、刷新origin/main后通过；这不证明真实CI或审批已发生，仍核对原始记录。
- [ ] 新建带注释、不可复用的`v0.1.0-rc.N`标签；目标tag CI通过后，GitHub Release必须标记**pre-release**，标题/正文明确“待部署验收”，不可设为正式latest。
- [ ] 登记接收负责人角色、交付日期、校验结论、维护期限和支持范围；真实联系人、密钥、初始密码和业务数据单独受控交接。

候选标签不会要求生产配置，CI制作源码与交付材料；稳定版本标签才运行强制production构建。未经维护者审核的开发提交仅可用`--draft`生成预检包，状态为draft-before-main-review，不冒充已批准候选交付。后续修复使用新rc版本/提交，不移动旧标签。

## B. 学校试点/正式上线（全部验收与签字）

以下原有门槛保留。任一必需项未完成时不得创建 Release（正式版），不得在学校正式开放使用；候选包/体验版不代表通过本节。

## 1. 范围冻结

- [ ] 目标提交已通过 PR 合入 `main`，检查与评审符合仓库规则；分支保护设置另外核实，不能从一次合并推断保护已启用。
- [ ] Milestone 中每个发布阻断 Issue 有优先级、负责人、验收标准和结论。
- [ ] `CHANGELOG.md` 的候选版本、已知限制、迁移和回滚与实际提交一致。
- [ ] `npm run release:check -- --production --tag --evidence /受控路径/acceptance.json` 在干净工作区通过。

## 2. 自动检查

- [ ] GitHub Actions 的 Backend tests、PostgreSQL concurrency、Miniprogram build policy 全部通过。
- [ ] Alembic 从空库升级和生产快照升级均通过。
- [ ] production 小程序产物的 `build-manifest.json` 记录正确版本与提交 SHA。
- [ ] 依赖审计结果已评估；未修复项有责任人、影响、缓解措施和期限。
- [ ] `docs/DEPENDENCY_LICENSE_INVENTORY.md` 与锁定依赖一致，素材和项目整体许可证已由权利人确认。

## 3. 外部配置与隐私

- [ ] 正式 AppID/AppSecret、HTTPS、合法域名和订阅模板由对应责任人确认。
- [ ] 强随机密钥、数据库账号和微信凭据只保存在学校密码库或受控环境变量中。
- [ ] 默认管理员凭据已移除或替换，并完成轮换和恢复演练。
- [ ] 校内身份验证/注册滥用防护由学校选定方案并验收。
- [ ] 隐私保护指引写明字段用途、权限、保存期限、删除与投诉渠道。
- [ ] 截图、日志、备份和验收数据不含真实个人信息或已按批准流程脱敏。

## 4. 运行与真机验收

- [ ] PostgreSQL 并发、API/worker 多实例、readiness、告警和优雅终止通过。
- [ ] 备份、校验、空环境恢复和回滚演练通过并保存证据。
- [ ] 学生、辅导员、管理员按 [演示与验收流程](DEMO.md) 在体验版完成主链路。
- [ ] 上传失败、弱网、401、5xx、重复提交、服务器重启和分页续载通过。
- [ ] 四类订阅消息至少各验证一次成功路径及失败不回滚业务路径。
